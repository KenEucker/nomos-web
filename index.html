Astro’s “Next.js / Nuxt.js” moment — but for full-stack

Build Astro apps with batteries included.

Nomos is a full-stack framework for Astro: opinionated structure, a Fastify-powered API layer, a pluggable admin UI, auth, and an extension system designed to stay simple and LLM-friendly.

Create a Nomos app npm Explore features ↓
⚡ Server + Admin in one place 🔌 WordPress-style plugins 🧠 LLM-friendly conventions 📄 OpenAPI / Swagger docs
nomos.config.ts 
// Nomos is to Astro what Next.js/Nuxt.js are to React/Vue:
// file-based structure + plugins + API + admin.

export default {
  app: { name: "Nomos" },

  plugins: {
    auth: true,
    admin: true,
    openapi: true
  },

  api: { basePath: "/api" },

  // Build domain features as plugins (enable/disable per-app)
  modules: [
    "./plugins/blog",
    "./plugins/users"
  ]
}

What Nomos gives you

Next.js and Nuxt.js feel productive because they bundle the “usual suspects.” Nomos does the same for Astro — without taking away Astro’s flexibility.

API layer built-in

A Fastify-powered API with consistent request/response helpers, clear errors, and patterns that scale from “one route” to “whole product.”

Admin UI that maps to your API

Resource-driven admin pages (list/create/edit) powered by your API. Keep the admin in the same server — like Laravel/WordPress-style productivity.

Plugin-first architecture

Drop-in modules with hooks + middleware registries. Enable/disable features per app, and keep domain features isolated and composable.

Auth + permissions ready

Session or token patterns, role checks, and a clean place to centralize access control so plugins don’t reinvent auth.

OpenAPI docs out of the box

Generate and serve OpenAPI/Swagger docs for your API so consumers (and LLMs) can discover routes and schemas automatically.

Conventions that scale

File-based structure, predictable module boundaries, and “best default” scaffolding to keep teams fast and projects coherent.

Developer experience like Next/Nuxt

Nomos focuses on the “inner loop”: fast scaffolding, consistent primitives, and a structure that makes feature work feel obvious.

One project, one deployment Keep your admin, API, and Astro pages together—deploy as a single unit, with consistent environment handling.
LLM-friendly by design Simple, explicit patterns (resources, endpoints, hooks) that help LLMs generate correct code and UI without “magic guessing.”
Docs that are always accurate OpenAPI docs derived from your code and config help teams and tools stay aligned.
Example: resource + API contract 
// Define once, use everywhere (admin, docs, clients).

export const usersResource = {
  id: "users",
  routeBase: "/admin/users",
  endpoints: {
    list: "/users",
    get: "/users/{id}",
    create: "/users",
    update: "/users/{id}",
    delete: "/users/{id}"
  },
  list: { searchable: true, pageSize: 20 }
}

How it fits together

Nomos keeps the mental model simple: Astro for UI, Fastify for API, and a plugin system to add domain features without turning your app into a tangle.

Astro frontend

SSR + islands, file-based pages, and a clean path for marketing, docs, and product UI.

Fastify backend

API routes, middleware, auth checks, and consistent error/response helpers.

Nomos plugins

Opt-in modules that register routes, admin resources, hooks, and shared utilities.
